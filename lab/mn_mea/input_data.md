# Входные данные MN-MEA: что подготовить

Проверить подготовленное:

```python
import inputs
замечания = inputs.check_inputs(h, geom)   # пустой список = годится
for n in замечания:
    print(n)
```

---

## 1. Обязательное: массив `h`

Единственное, без чего алгоритм не запустится.

| | требование |
|---|---|
| форма | `(M, N)` — **первый индекс доплер, второй дальность** |
| тип | комплексный: `complex64` или `complex128` |
| `M` | число импульсов в апертуре, не меньше 16 |
| `N` | число стробов дальности, не меньше 1 |
| раскладка по `k` | как у `numpy.fft`: нулевая частота в индексе 0, положительные дальше, отрицательные с конца |
| значения | ни одного `NaN`, ни одной бесконечности |

**Что это за данные.** Дальность-доплер ПОСЛЕ сжатия по дальности,
исправления миграции по дальности и прямого ПФ по азимуту — вход блок-схемы
§7 документа. Ни сжатия, ни миграции алгоритм не делает.

**Чего можно не делать:**

* нормировать — энтропия (5-6) от общего множителя не зависит;
* доводить `M` до степени двойки — проверено на `M = 250` и `M = 251`;
* вычитать среднее, выравнивать уровни.

**Если данные пришли центрированными** по доплеру (нулевая частота в
середине оси) — один вызов:

```python
h = numpy.fft.ifftshift(h, axes=0)
```

`inputs.check_data` это заметит и скажет, но только если сигнал занимает не
всю полосу. Если занимает — проверка промолчит, следите сами.

## 2. Для разбиения на блоки: `Geometry`, 14 чисел

Нужно **только** этапам A и B. Этапы C и D геометрию не читают вовсе.

| поле | что | единицы | откуда |
|---|---|---|---|
| `v_x0, v_y0, v_z0` | скорость носителя | м/с | ИНС/GPS на середину апертуры |
| `a_x, a_y, a_z` | ускорение носителя | м/с² | оттуда же |
| `x_m, y_m, z_m` | центр сцены относительно носителя | м | геопривязка |
| `R_B0` | наклонная дальность до центра сцены | м | геометрия съёмки |
| `f_0` | несущая частота | Гц | паспорт станции |
| `r_a` | разрешение по азимуту | **м на отсчёт** | паспорт обработки |
| `r_b` | разрешение по дальности | **м на отсчёт** | паспорт обработки |
| `T_a` | время синтеза | с | паспорт обработки |

Два условия, которые проверяются:

* `R_B0` обязан равняться `|(x_m, y_m, z_m)|` — это одна и та же точка;
* скорость не ноль, иначе (5-27)/(5-28) не определены.

Скорость и ускорение берутся **по одному числу на всю апертуру** — так
устроена книга. Берите значение на её середину.

**`lambda_` готовить не нужно.** Поле в `Geometry` есть, но алгоритм не
читает его ни разу: длина волны входит через `c / f_0`.

## 4. Если ИНС нет

**Ничего страшного, и это замерено.** Полный прогон на изменчивой ошибке,
три сцены:

| что известно | сетка блоков | контраст | пик |
|---|---|---:|---:|
| всё: ИНС, этапы A и B по книге | 6×2 от (5-20) | 33,80 | 99,8 |
| ИНС есть, но `φ⁰ = 0` | 6×2 от (5-20) | 34,24 | 100,5 |
| **ИНС нет: сетка 6×2 руками** | 6×2 | **34,24** | **100,5** |
| ИНС нет: сетка 4×2 руками | 4×2 | 33,86 | 100,1 |
| **ИНС нет: сетка 8×3 руками** | 8×3 | **35,45** | 100,2 |
| ИНС нет: один блок на сцену | 1×1 | 27,06 | 97,4 |

Читается это так.

**Сетка, выбранная руками, не хуже сетки от ИНС.** Строки 2 и 3 совпадают
до сотых: при `φ⁰ = 0` геометрия не влияет ни на что, кроме числа блоков, а
число блоков можно назвать и самому.

**Книжная начальная фаза (5-30) не помогает, а мешает:** 33,80 против 34,24
при `φ⁰ = 0`. Причина замерена и описана в README — неразъяснённый член
`−(q−q_k)/2` в (5-29) уводит `η` в диапазон около [−6, +0,6]. То есть этап B
можно не делать вовсе, и станет лучше.

**Единственное, что действительно важно, — делить сцену на блоки.** Один
блок даёт 27,06 против 34–35 у любого разбиения. Разница между 4×2, 6×2 и
8×3 меньше, чем разница между «делим» и «не делим».

### Что делать без ИНС

1. Выберите сетку блоков сами. Разумная отправная точка — блок в 30–60
   отсчётов по азимуту; при `M = 256` это `M_k` от 4 до 8.
2. Стартуйте с `φ⁰ = 0`. Этап B пропускается целиком.
3. Прогоните две-три сетки и сравните контраст собранной картинки —
   `validate.image_sharpness`. Это займёт минуты и заменит ИНС.

`Geometry` при этом всё равно нужна `block_grid` как аргумент — но из неё
читаются только `r_a` и `r_b`, чтобы посчитать координаты центров блоков в
метрах. Если и их нет, поставьте единицы: на результат это не влияет, пока
`φ⁰ = 0`.

## 5. Чего НЕ нужно

| | почему |
|---|---|
| истинная фазовая ошибка | на записи её никто не знает — она и есть искомое |
| опорная сфокусированная картинка | не с чем сравнивать и не нужно |
| разметка целей | алгоритм их не ищет |
| ИНС на каждый импульс | книга берёт одно число на апертуру |
| `matplotlib` | нужен только стенду, не алгоритму |

Всё перечисленное есть **только на стенде** (`bench/`), и потому стенд лежит
отдельно от `algorithm/`.

## 6. Наименьший рабочий пример

```python
import sys
sys.path.insert(0, "algorithm")

import numpy as np
from backend import get_backend
import inputs
import stage_c_iterate as C
import stage_d_assemble as D

h = ...                       # ваш массив (M, N), комплексный
assert not inputs.check_data(h), inputs.check_data(h)

backend = get_backend("auto")          # видеокарта, если она есть и РАБОТАЕТ
h_dev = backend.asarray(h)
M, N = h.shape

result = C.iterate_block(backend, h_dev, np.zeros(M), mu=1e-3)
phi = D.remove_image_shift(backend, result.phi)        # решение №5
image = D.block_image(backend, D.azimuth_window(backend, h_dev), phi)

print("сошлось:", result.converged, "за", result.n_iterations, "итераций")
print("энтропия:", result.normalised_entropy_history[0],
      "->", result.normalised_entropy_final)
```

Это один блок на всю сцену, без геометрии. Для разбиения добавьте `Geometry`,
`stage_a_blocks.block_grid` и цикл по блокам — как в
`bench/validate.experiment_full_run`.
